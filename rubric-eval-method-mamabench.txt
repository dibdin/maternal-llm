Rubric-Graded Evaluation: Dataset and Methodology

For the rubric-graded evaluation track, we use a maternal/neonatal-scoped subset of HealthBench (Arora et al., 2025), specifically its open-source evaluation split (oss_eval). HealthBench is a physician-authored benchmark in which each prompt is paired with a set of quality rubric criteria written by practising clinicians; model responses are scored by an LLM judge on a per-criterion YES/NO basis, and the final score is the proportion of criteria met across items.

Why HealthBench oss_eval rather than the full set. The full oss_eval split contains 5,000 items spanning all medical specialties. We restrict to the 487 items that match our evaluation domain using keyword filtering on the user prompt — terms covering pregnancy, labour, delivery, postpartum care, neonatal health, breastfeeding, obstetric complications, gynaecological conditions, and reproductive health. This is conceptually identical to the scope-filtering step performed by the mamabench benchmark (Ren Yi, 2025), which uses an LLM classifier on the same oss_eval split to identify 1,209 in-scope items. Our filtered subset is a stricter, more conservative draw from the same pool — items that unambiguously use maternal/reproductive health terminology. The practical difference is one of recall, not precision: the mamabench classifier may retain items where the clinical concept is maternal but the wording is indirect; our keyword filter retains only those where the domain is lexically explicit. For a pilot study, this conservative approach reduces the risk of including out-of-scope items while still yielding a sufficiently large evaluation set.

Why we use oss_eval and not the mamabench-distributed CSV. The mamabench benchmark distributes its rubric-graded subsets in a schema that stores criterion IDs and point values but omits the criterion text itself, which must be joined back from the source HealthBench data. The oss_eval.jsonl file from HealthBench includes full criterion text inline for every item. By filtering directly from this source file we retain criterion text without requiring an additional join step, which keeps the pipeline self-contained and reduces the risk of data linkage errors. The resulting dataset (mamabench_rubric.csv) is therefore both domain-scoped and fully enriched with criterion text ready for judge evaluation.

Evaluation procedure. For each of the 487 items we generate a model response and then call a LLM judge (gpt-4o-mini) on each criterion individually, asking it to return YES or NO. The item score is the proportion of criteria met; the final reported metric is the mean proportion across all items. This follows the HealthBench evaluation protocol directly.
